# 技术更新：减少模型调用与重复上下文

日期：2026-11-07。范围：Modbus LangGraph、页面/CLI/MCP入口、运行计量。原始评测及用户验收记录保留。

## 为什么要改

用户的一次简单问题运行消耗输入9164、输出3376、总12540 token，4次调用，耗时35.781秒，见`data/modbus/runs/a5cb0dbdc9a240d081406d4c29eb6020.json`。该历史记录未保存问题全文和逐次调用明细，不能断定四次调用分别是什么，也不能把新问题的结果作为该次请求的严格前后对照。

检查代码发现两个可明确消除的开销：

1. 简单协议概念题也执行“模型选择检索→读取结果后再决定finish→最终回答”，格式修正还可能增加调用。
2. 决策节点每次接收完整工具观察，其中有文档正文。最终生成节点又同时接收这些观察和citations正文，同一证据重复发送。多次检索进一步累积重复内容。

本次目标是减少不必要的决策调用和重复传输，不修改检索算法、模型价格、思考模式或协议事实，不以省token为由删除引用或放宽事实校验。

## 改动一：简单文档题走固定快路径

两条路径都保留在同一个LangGraph中：

```text
auto + 明确文档题 + 未提供日志：
START → retrieve_direct（本地检索）→ respond（一次生成）→ END

其他情况或显式agent模式：
START → decide → tools → decide … → respond → END
```

路由不调用模型：要求问题不超过600字符、包含Modbus/功能码/寄存器/异常码等领域词，并有解释、定义、区别等明确文档问法。出现现场、我的、故障、日志、根因、排查、超时等词，或提供了日志（包括空数组），保守地走完整Agent。未匹配时不猜测为简单题。

快路径复用现有search_docs处理和respond节点，因此仍保留文档引用、失败处理和编号检查。无检索证据时不调用生成模型，返回证据不足。正常有证据的简单题目标为1次模型调用；不保证每次生成都成功。

入口行为：

- 页面“运行Agent”和MCP的run_modbus_agent默认auto；结果展示execution_path。
- CLI默认auto，可用`--execution-mode agent`强制完整循环。
- Python核心`ModbusAgent.run`默认仍为agent，保持现有调用兼容；使用快路径需显式传`execution_mode="auto"`。原评测器不改默认模式，便于保留参考路径。
- “只检索文档”仍是无模型的摘录模式，不被偷偷改成付费生成。

示例：页面选择“不提供日志”，输入“请解释Modbus功能码03和04的区别，并引用官方文档”。若选择模拟日志，同一问题仍走日志/Agent路径；用户显式提供的日志不会被静默忽略。

## 改动二：按节点发送必要上下文

新增compact_observations，仅构造发送给模型的视图，不删改状态里的原始观察。

| 内容 | 决策节点 | 最终回答节点 | 页面/导出 |
|---|---|---|---|
| 文档正文 | 每片最多180字符预览与编号/页码/类型 | citations中每个chunk一份完整正文 | 完整保留 |
| 多次检索返回同一片段 | 可有重复编号，正文不全量累积 | 沿用chunk_id证据集合去重 | 原工具记录保留 |
| 日志事务事实 | 保留必要结构化字段 | canonical_log_facts一份 | 完整分析可查看 |
| 通用限制说明 | 不当作事件事实重复传递 | 不作为日志证据传递 | 原分析仍可核对 |

180是字符上限，不是token上限；预览是程序截取，不额外调用模型生成摘要。最终生成仍取得完整已检索片段及来源，保留从站/寄存器地址、数量、状态等事实验证。程序截取可能不足以支持复杂决策，因此复杂流程的质量仍需复核。

## 计量与可解释性

- 结果与本地运行记录新增execution_path：simple_document或full_agent。
- 每次调用记录request_characters，表示系统与用户消息内容字符数；不保存提示词原文，也不将字符数冒充API token。
- 输入/输出/总token继续使用服务商返回usage，格式重试和生成重试均计入调用。
- 费用仍为已核对公开价估算，不是账单。未为此次优化关闭思考模式或改动模型，避免混淆实验因素。

## 验证方法与报告

1. `tests/unit/test_modbus_call_optimization.py`：验证快路径一次生成、无证据零调用、诊断/日志题保留完整路径、决策预览不含完整长证据、最终请求正文只出现一次；完整状态仍保留全文。
2. 页面、MCP、协议事实、引用校验与计量相关测试回归。
3. `data/modbus/evaluation/context_payload_comparison.json`：对固定历史A06状态比较旧/新上下文JSON字符数，排除系统提示，不是token测量。
4. `python -m scripts.benchmark_modbus_calls`：用同一问题对比agent与auto路径，调用真实API，会产生费用。逐模式结果、trace、回答、费用和用量保存在`data/modbus/evaluation/call_optimization_comparison.json`。

真实配对实验的两条路径均已使用紧凑上下文，因此它隔离的是路由效果；不能声称测出了“旧版全文重复上下文”到新版的全部token收益。模型生成、缓存和服务时延存在波动，一次实验也不能代表普遍准确率或生产P95。

## 风险与后续

- 规则路由是保守启发式，不是完美意图识别。误分简单题时可能一次检索不足；强制agent模式可作为对照入口。
- 决策预览可能丢失条件，完整原文仅在回答节点使用；复杂故障用例需要继续回归。
- 仍然只检查引用编号及结构化日志事实，不能自动证明解释的每句话都成立。
- 暂未自动判断“再检索没有新增证据就结束”，也未把常规日志流程全部改成一次调用，避免一次改太多影响定位。
- 后续使用更多新问题评估质量与成本，再决定是否加入决策专用非思考配置、检索预算与缓存。
